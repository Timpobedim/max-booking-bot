# Шиномонтаж «Колесо» в MAX — клиент MAX Bot API и бот записи

Две части. `maxkit` — небольшой клиент MAX Bot API: методы, темп запросов, ограниченные повторы,
long polling с сохранением маркера, inline-клавиатуры, двухшаговая загрузка файлов, маршрутизация
событий и эмулятор API для тестов. `tyre_bot` — бот на нём: клиент шиномонтажа выбирает услугу, день
и время, делится номером телефона и получает подтверждение, а мастера — уведомление в своём чате.
Отмена — в два нажатия.

**Стек:** Python 3.12 · httpx · SQLite · pydantic-settings · pytest · ruff · mypy (strict) · uv.

## Бот записи

- **Услуги:** сезонная замена колёс R13–R16 (40 минут, 2400 ₽) и R17–R22 (60 минут, 3600 ₽),
  балансировка (30 минут, 1600 ₽), ремонт прокола (30 минут, 800 ₽).
- **Свободное время:** сетка по 30 минут в часы работы; на ближайшие полчаса не записываем; одновременно
  обслуживается столько машин, сколько подъёмников (`TYRE_BOT_POSTS`). Занятость считается как наибольшее
  число записей, идущих одновременно на отрезке, а не как число пересечений: записи 9:00–9:30 и 9:30–10:00
  не мешают третьей записи на 9:00–10:00 при двух подъёмниках.
- **Двойная запись невозможна.** Запись создаётся в транзакции `BEGIN IMMEDIATE`: проверка места и
  вставка идут под блокировкой базы. Если двое нажали одно время, второй получает «только что заняли» и
  новые варианты (тест `test_second_client_cannot_take_the_busy_slot`). Повторное событие после
  перезапуска бота не создаст вторую запись — это держит уникальный индекс (клиент, время).
- **Выбор клиента не теряется** при перезапуске: черновик (услуга, день, время) хранится в SQLite, а маркер
  событий — в файле рядом с базой.
- **Телефон** — кнопкой «Поделиться номером» (контакт с vCard) или сообщением в любом виде:
  «8 (900) 123-45-67» → `+79001234567`.
- **Мастерам** в чат `TYRE_BOT_ADMIN_CHAT_ID` приходят новые записи и отмены; `/my` показывает клиенту
  его записи с кнопками отмены, а чужую запись отменить нельзя.

## Быстрый старт

```bash
uv sync --group dev
cp .env.example .env      # TYRE_BOT_MAX_TOKEN и TYRE_BOT_ADMIN_CHAT_ID
uv run tyre-bot
```

`maxkit` можно взять для своего бота:

```python
from maxkit import MaxApi
from maxkit.longpoll import LongPoll
from maxkit.router import Context, Router

router = Router()

@router.command("/start")
def start(ctx: Context) -> None:
    ctx.reply("Здравствуйте!")

with MaxApi(token) as api:
    for update in LongPoll(api, marker_file=Path("data/bot.marker")).listen():
        router.dispatch(api, update)
```

## Структура

```text
src/maxkit/
├── client.py      # MaxApi: методы, темп 30 запросов в секунду, повторы, загрузки
├── longpoll.py    # поток событий с маркером в файле
├── keyboard.py    # inline-клавиатуры
├── types.py       # события: сообщение, нажатие кнопки, запуск бота, контакт
├── router.py      # команды, кнопки, сообщения → обработчики
└── testing.py     # эмулятор MAX Bot API для тестов ботов
src/tyre_bot/
├── bot.py         # диалог записи
├── schedule.py    # услуги, сетка времени, загрузка подъёмников
├── storage.py     # записи и черновики в SQLite
├── settings.py    # настройки из .env
└── __main__.py    # запуск: long polling → маршрутизатор
tests/             # 37 тестов
```

## Как проверялось

Windows 10, Python 3.12 (uv):

- `ruff check`, `ruff format --check`, `mypy` (strict, 13 файлов) — без ошибок;
- `pytest` — 37 тестов: клиент (10), long polling (3), события и клавиатуры (9), расписание, телефоны и
  хранилище (11), диалог записи целиком — от приветствия до подтверждения, гонка за одно время, неверный
  телефон, просмотр и отмена записи (4).

Не проверялось: живой MAX Bot API — токена бота нет. Запросы следуют документации dev.max.ru (сентябрь
2026): адрес `platform-api2.max.ru`, токен в заголовке `Authorization`, 30 запросов в секунду, `GET
/updates` с маркером, `POST /answers`, `POST /uploads`. Формат вложения-контакта (vCard в `vcf_info`)
и ответ сервера загрузки проверены только на эмуляторе.
